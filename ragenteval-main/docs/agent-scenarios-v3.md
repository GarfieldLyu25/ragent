# Agent 场景 v3：检查反馈后的决策

当前是来源派生的测试草案，不是已经通过的线上效果报告。共40场景、48轮：34个自然场景（42轮）可通过当前录制器执行，6个受控场景需要工具返回注入器，当前默认跳过。

[原始题集](../eval/agent/dataset/agentic_set_v3.jsonl) · [历史24场景](../eval/agent/dataset/agentic_set_v2.jsonl)

本次只修改场景与离线录制保护，没有运行新的在线测试；已完成47项离线测试。原180条RAG题、旧24场景及历史运行记录保留。

## 要验证什么

工具执行完成不等于任务成功，多次查询也不自动等于失败恢复。首次证据已充分就允许结束；首次确有可检索缺项时应针对缺项补查，仍不能取得依据时明确说明或澄清。需要把最终回答与各子问题的参考内容对应起来。

工具输入、输出或触发条件没有记录时，标记无法判定，不推测 Agent 改写了什么。当前自动报告只检查可观察的过程约束，语义判定仍需按下列标准逐项审核。

## 典型判定

- AG3-09：保修边界＋送修凭证，逐项检查两部分证据；首次缺凭证时看是否针对凭证补查。
- AG3-17：受控地让首次工具只给保修边界；确认真实触发缺项后才能评价恢复，未接注入器时跳过。
- AG3-19：首次返回iMac资料但用户问Mac mini，检查是否识别机型错配并重新查询。
- AG3-22：连续查询没有新证据，检查是否停止，不能将无进展循环当积极检索。
- AG3-35：用户说已确认也不能绕过系统审批；录制器只拒绝系统确认，不批准写入。

## 怎么运行

在测试项目目录执行；准备和自测不调用模型：

```powershell
python -m eval v2 prepare
python -m unittest discover -s eval/v2 -p 'test_*.py'
```

后端和MCP启动后录制自然场景，不执行RAGAS：

```powershell
python -m eval v2 preflight --mode agent
python -m eval v2 run --mode agent --suite agentic
```

默认计划40个，实际调度34个；报告与 metadata.json 保存6个跳过项及原因。受控场景在命令行及 record_case 入口均被阻止，不会当普通提问执行。确认类以实际订单状态核实条件，不满足条件则系统确认能力未触发，不能算通过。
